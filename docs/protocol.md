# P31n 遥测协议版本 1

服务 UUID 为 `A0310000-5B5A-4B4D-9A6E-5033314E0001`。事件特征为相同后缀的 `A0310001`，控制/状态特征为 `A0310002`。

事件通过 GATT Notifications 发送，每包 20 字节，适配默认 ATT MTU 的有效载荷。控制和状态读写要求加密连接；控制命令仅接受当前蓝牙档位对应的主机，事件也只发往该主机。

## 事件

| 偏移 | 字节数 | 字段 |
| --- | --- | --- |
| 0 | 1 | 协议版本，固定为 1 |
| 1 | 1 | 物理位置，0～30 |
| 2 | 1 | 状态，1 按下、0 松开 |
| 3 | 1 | 保留，固定为 0 |
| 4 | 4 | 本会话事件序号，小端 |
| 8 | 4 | 原始位置事件的 uptime 毫秒，小端 |
| 12 | 4 | 本次启动标识，小端 |
| 16 | 4 | 采集会话标识，小端 |

位置 25 是中央 1.5u 黑色键。位置排序保持 `p31n.overlay` 的矩阵 transform 顺序；实际几何和左右手归属由 `P31nGeometry` 定义。协议不包含 QMK keycode，也不将当前层、逻辑输出或并击结果伪装成物理事件。

## 控制与状态

写入一个字节：`1` 开启新采集会话并清零计数；`0` 停止。开始前需要订阅事件通知。每次 START 都递增 session，事件序号从 0 开始。

状态读为 32 字节：版本位于 0，enabled 位于 1；偏移 4、8、12、16、20、24、28 依次为 boot ID、session、captured、sent、dropped、replayed、next sequence，各为小端 uint32。2～3 字节保留。

`sent` 表示已交给蓝牙栈，不是接收应用的确认。队列溢出或发送失败计入 dropped；接收端用序号另行检测遗漏。Notifications 没有应用级确认和历史补发，本版本不承诺应用退出或断连期间完整记录。

## 配对与会话边界

计时只用设备时间戳，不用 Mac 收包时间。uint32 uptime 在约 49.7 天回绕，按无符号减法处理。boot ID 或 session 改变时清除未完成配对；发现序号缺口时也清除，避免跨丢失区间累计时长。

新采集会话可能开始于某个键已经按住的时刻，第一条松开没有对应按下时不累计该键的时长。受控验证须先松开所有键。

队列和去重历史各容纳 128 个事件。日常兼容性、异常情况和本地调试入口见 [验证路线](validation.md)。固件与两个 Mac 客户端的字段必须同步更新；机器可读定义见 [protocol.json](../protocol.json)。
